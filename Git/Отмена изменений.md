1. **Уровень 1** - изменения только в рабочей директории
	1. `git restore <имя_файла>` - Стирает все изменения в конкретном файле, возвращая его к состоянию на момент последнего коммита.
	2. `git restore .`  - Отменяет изменения во **всех** существующих файлах текущей папки.
2. **Уровень 2** - изменения добавлены в индекс.
	1. `git restore --staged <имя_файла>` или `git reset HEAD <имя_файла>` - Убирает файл из индекса (он снова становится «красным»). Сам код внутри файла **не меняется** и не удаляется.
	2. `git reset HEAD .` - cбрасывает из индекса сразу все подготовленные файлы. Код на диске остается нетронутым.
3. **Уровень 3** - Изменения уже в коммите (но ЕЩЕ НЕ отправлены в удаленный репозиторий)
	1. `git commit --amend -m "Новое сообщение"` - просто ошибся в тексте сообщения или забыл добавить один файл (сделай сначала `git add`), эта команда не создает новый коммит, а перезаписывает самый последний.
	2. `git reset --soft HEAD~1` - Самый безопасный сброс. Удаляет последний коммит из истории, но **сохраняет весь твой код**. Все изменения из этого коммита возвращаются в индекс (становятся «зелеными»). Отлично подходит, если нужно переписать коммит заново.
	3. `git reset --mixed HEAD~1` - Удаляет последний коммит. Код остается на диске, но изменения вылетают из индекса (становятся «красными»).
	4. `git reset --hard HEAD~1` - Полностью уничтожает последний коммит, очищает индекс и физически стирает код этих изменений с диска. Проект возвращается к состоянию предпоследнего коммита.
4. **Уровень 4** - коммиты уже отправлены в удалённый репозиторий
	1. `git revert <хэш_коммита>` - Безопасный способ. Git анализирует изменения в указанном коммите и создает **новый коммит, который делает всё ровно наоборот** (если там строка добавлялась — он её удалит). История остается чистой, граф не ломается.

---

Как спасти код, если случайно сделал `git reset --hard`?

Если ты случайно стёр коммит жестким сбросом, не паникуй. Пока Git не запустил автоматический сборщик мусора, коммит все еще лежит в `.git/objects`.

1. Введи команду `git reflog` (это журнал всех передвижений указателя HEAD).
2. Найди строчку, которая была прямо _перед_ роковой ошибкой (там будет написан хэш коммита).
3. Введи `git reset --hard <хэш_из_reflog>`, и Git вернет всё на место.

---

Отличие команд `git restore` от `git reset`

Если говорить максимально просто:

- **`git restore`** создана исключительно для **отката изменений в файлах** (в рабочей директории или в индексе). Она работает с _файлами_, но не трогает историю коммитов.
- **`git reset`** создана для **управления историей и передвижения указателя ветки (HEAD)**. Она перемещает саму ветку на другой коммит, а файлы на диске меняются уже как _следствие_ этого перемещения.
