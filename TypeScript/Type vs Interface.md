**Интерфейс (`interface`) — это объявление (Declaration).** Он жестко фиксирует имя и структуру. Ты не можешь написать `interface A = B | C;` или `interface A = B & C;`, потому что знак `=` означает присвоение результата выражения.
 
**Псевдоним типа (`type`) — это определение через выражение (Assignment).** Он работает как переменная в JS, только для типов. Он может принять в себя результат любой операции: пересечения (`&`), объединения (`|`), условного типа (`extends ? :`) или дженерика.

Если говорить коротко: **`interface` описывает форму объекта**, а **`type` описывает вообще любой тип данных** (объект, примитив, объединение, функцию и т.д.).

Различия типов и интерфейсов:
1. Интерфейсы поддерживают декларативное слияние, а псевдонимы типов нет.
2. Результат пересечения двух типов - тип, результат пересечения двух интерфейсов - тип.
3. Результат объединения (union) двух типов - тип, результат объединения двух интерфейсов - тип.
	   Объединение/пересечение — это динамическое выражение, а результат любого выражения в TS можно сохранить только в псевдоним типа (`type`).
4. С точки зрения **синтаксиса и ключевых слов** : псевдонимы типов (`type`) **не поддерживают ключевое слово `extends`** (наследование в классическом понимании), в то время как интерфейсы (`interface`) созданы именно для этого. Однако с точки зрения **возможностей**, типы могут делать абсолютно то же самое, но с помощью другого инструмента — **пересечения (`&`)**.

В современных командах разработки обычно договариваются об одном из двух подходов:
1. **Интерфейсы по умолчанию:** Для всех объектов, моделей данных, компонентов и API-ответов используется `interface`. Ключевое слово `type` используется _только_ тогда, когда возможностей интерфейса не хватает (нужен Union, кортеж или сложные вычисления).
2. **Типы по умолчанию:** Используется только `type` для всего, ради единообразия кода. А `interface` берется только при написании публичных библиотек, где нужно слияние деклараций.
